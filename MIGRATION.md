# Архитектурная миграция: LLM-centric система

## Что изменилось

### 1. Единая точка входа — LLM (LLMInterface)

**Раньше:**
```
User → Classifier → [activate llm/logic] → Logic/LLM → Response
```

**Теперь:**
```
User → LLM (active) → [если нужно: call Logic] → LLM + Result → Response
```

LLM всегда загружена и готова. Она анализирует запрос с системным контекстом и сама решает:
- Ответить пользователю из контекста
- Вызвать Logic через `[LOGIC_REQUEST: ...]`

### 2. Удалены компоненты

- **IntentClassifier** (`core/classifier.py`) — логика классификации перешла в LLM system prompt
- Жесткая логика переключения моделей заменена на гибкую

### 3. Новые компоненты

- **LLMInterface** (`core/llm_interface.py`) — главный интерфейс взаимодействия
  - Обработка запросов пользователя
  - Парсинг `[LOGIC_REQUEST]` из ответа
  - Форматирование результатов для пользователя

- **ContextStore** (`core/context_store.py`) — хранилище контекста
  - Сохранение событий системы
  - Предоставление контекста LLM
  - Сокращение нагрузки на модели

### 4. Оптимизация памяти

- LLM остаётся в памяти (основной интерфейс)
- Logic загружается по запросу LLM
- Переключение через `ModelOrchestrator.activate_logic()`

### 5. Изменения в OperatorApp

**Новые методы:**
- `handle_message()` — единая точка входа
- `_execute_logic_request()` — обработка запросов Logic
- Удалены: `chat()`, `execute_action()`, классификация

**Новые поля:**
- `llm_interface` — LLM интерфейс
- `context_store` — хранилище контекста

## API использования

### Из CLI

```bash
# LLM решает сама
> Создай файл todo.txt
# → LLM парсит, видит действие, вызывает [LOGIC_REQUEST]
# → Logic выполняет, LLM форматирует ответ

# Принудительное действие
> /do Создай папку backup
# → Напрямую в Logic, без LLM классификации

# Просмотр контекста
> /context
# → Показывает, что "видит" LLM
```

### Из кода

```python
app = OperatorApp()
await app.startup()

# Любое сообщение идёт через LLM
response = await app.handle_message("Создай файл")
```

## Миграция Logic system prompt

Logic получает **краткий summary** от LLM вместо полного текста запроса:

**Раньше:**
```
User: "создай файл с названием report.txt в папке документов"
→ Classifier → Logic
```

**Теперь:**
```
User: "создай файл с названием report.txt в папке документов"
→ LLM парсит → `[LOGIC_REQUEST: Создать текстовый файл report.txt в стандартной папке документов]`
→ Logic получает: "Создать текстовый файл report.txt в стандартной папке документов"
```

## Совместимость

- Все существующие модули, операции, plans — без изменений
- Logic ядро работает точно так же
- Recovery механика без изменений
- Только интерфейс и управление моделями изменились
